# WP-CA01-design-20261011

**Control.** CA-01, version control over all source, rule data and documentation.

**Test method and reason.** Inspection, because design effectiveness is assessed
by inspecting configuration and documents rather than by observing operation.
Two inspections per PLAN.md section 4: author identity over the commit
population for attributability, and reconciliation of the tracked file list
against the contents of a clean non-editable install, to confirm that
everything shipped to a user is under version control. Deviation: the venv is
created in a session scratchpad directory (shown as `<SCRATCH>` below; the
full path appears unedited in the `pip show` output) rather than `/tmp`.

**Population and regime.** Not applicable, design test. The object under test is
a fresh clone of `https://github.com/beestru/eu-ai-act-triage` taken at
2026-10-11 11:04:37 UTC, fieldwork day one of the window restarted by the
STATE.md ruling of 11 October 2026: `main` at commit
`7aab9f95065f9cf69cbdefe5a9aed64c361386ce`, 45 commits, tags v0.1.0 to
v0.5.0.

The reconciliation excludes three classes of installed file, none of which is
source: the generated console-script launcher (`../../../bin/aiact-triage`),
packaging metadata (`dist-info/`), and bytecode compiled at install
(`__pycache__/`). Every remaining installed file maps one to one to a tracked
file under `src/aiact_triage`, rule data included.

**Executed.** 2026-10-11, 12:04 BST.

**Conclusion.** Design effective: every one of the 45 commits on `main` is
attributable to a single account address, and everything a clean
non-editable install ships reconciles exactly to the tracked file list, so
nothing a user receives sits outside version control. Observed and not
resolved here: the population carries two author display names on that one
address (44 commits as `Bastian Struve`, one as `BeeStru` with committer
`GitHub <noreply@github.com>`); whether that breaks the consistent-identity
criterion is CA-01's operating test.
